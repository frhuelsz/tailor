# Tailor 1.0 implementation plan

Status: Implemented (see [implementation status](#implementation-status))
Supersedes-input: `2026-09-10-tailor-1.0-readiness.md` (the critique this plan resolves)
Baseline: workspace `0.8.0` @ `049175e`

This plan turns the 1.0-readiness assessment into a phased, actionable
roadmap. Every area below was decided in a maintainer decision pass; the
[decision log](#decision-log) records each choice verbatim. Phases are ordered
by dependency and can each land as one coherent, pushed change set behind a
green `just check`.

## Implementation status

All phases below were implemented and landed on `main` (CI green). Two
decisions were refined during implementation once the code was inspected — both
achieve the decision's intent with less machinery, and are flagged here for
review:

- **Engine version in the fingerprint** — implemented as the
  `BUILD_SCHEMA_VERSION` const only, **not** a separate IC-version probe. The IC
  engine version is already captured with full precision by the digest-pinned
  toolchain image reference (`toolchain_digest`), which is folded into the
  fingerprint; a different IC build is a different digest, hence a different
  fingerprint. A runtime probe would be redundant work, so it was omitted and a
  regression test locks the digest→fingerprint property in.
- **Lock coverage** — the genuinely-unpinned remote input was the **janitor
  image**, which is now resolved and pinned by `tailor lock`/`update`. The
  toolchain (**engine**) and **tools-dir** sources were already pinned. The
  remaining decision targets — `rpmSources`, `extraDependencies`, and `inputs` —
  are repo-local files (or tailor's own produced artifacts) already content-
  hashed into the incremental fingerprint for build correctness, and are
  versioned by git; they were **not** added to the remote-digest lockfile.
  Adding local-content drift-locking to `tailor.lock` remains available as a
  follow-up if desired.

## Scope & guiding principles

- **Scope: standard** — ship the P0 blockers and most P1 items; push the rest to
  a documented post-1.0 roadmap.
- **The 1.0 contract is the `tailor` CLI only.** The library crates
  (`tailor-core`, `tailor-exec`, `tailor-config`, `tailor-sign`) are **not**
  covered by semver for 1.0 — declared unstable via a `README`/`lib.rs` note and
  `#[doc(hidden)]` on internal-only re-exports. Cheap, and frees internal
  refactors post-1.0.
- **Parallelism is deferred** (see [post-1.0](#deferred-to-post-10)). 1.0 builds
  sequentially; `--jobs` is hidden. The *concurrency-safety groundwork* (atomic
  writes, single-worktree guard) still lands in 1.0 so parallelism is a safe
  drop-in later.
- **Preview features gate anything not yet stable.** A new workspace-level
  `previewFeatures` list (mirrors IC) is the single opt-in mechanism; using a
  gated capability without it is a hard load-time error.

## Phase 0 — Correctness fixes (P0)

These are latent bugs; they block 1.0 regardless of features.

1. **Engine/build version in the fingerprint.** Today `stamp.is_up_to_date`
   ignores the recorded version and the fingerprint omits the engine → after a
   tailor/IC upgrade a stale cached image is silently reused.
   - Fold **both** a hand-maintained `BUILD_SCHEMA_VERSION` const **and the
     probed IC engine version** into `FingerprintInputs`. The IC version is the
     dominant cache-invalidation driver; the const covers the rarer tailor-side
     build-semantics change.
   - Files: `tailor-core/src/fingerprint.rs` (new inputs),
     `tailor-core/src/stamp.rs`, engine-version probe in `tailor-exec`.
2. **Selector must not exclude a producer.** A single `Selector` is applied to
   every topological node, so `tailor build <consumer> -s …` can filter out a
   producer's paired cell; the consumer then resolves a path to an artifact that
   never builds.
   - Union each producer's dependency-required coordinates into its own
     selection so a dependency is always built even when filtered out of the
     top-level selection.
   - Files: `tailor/src/run.rs` (per-node topological loop).
3. **Atomic writes** for stamp, hash-cache, and published artifacts:
   temp file → `fsync` → `rename`. Prevents torn state on crash/interrupt and is
   the groundwork for future parallelism.
   - Files: `tailor-core/src/{stamp.rs,hashcache.rs}`, `tailor-exec/src/executor.rs`.
4. **Single-worktree build guard.** Refuse to start a build when another build
   is already running in the same worktree (advisory lock on a well-known path).
   - Files: `tailor/src/run.rs` (or a small `tailor-core` guard helper).

## Phase 1 — Stability contract

1. **Enforce `schemaVersion` (major-strict).** Reject an *unknown major*; a
   newer minor is tolerated (forward-compatible). A mismatch is a clear,
   actionable load error naming the supported version.
   - Files: `tailor-config/src/loader.rs`, `schema.rs` (const of supported major).
2. **Per-image versioning: inherit.** Images and fragments inherit the workspace
   `schemaVersion`; they do **not** carry their own. One version knob.
3. **`COMPATIBILITY.md`** — the published semver promise. In scope for 1.0:
   **CLI commands/flags**, **config schema (+ a migration path)**, **slug /
   artifact filename stability**, and the **exit-code taxonomy**. Explicitly
   *not* promised for 1.0: stdout/JSON format, lockfile format, MSRV, and a
   formal deprecation policy (documented as unstable).

---

## Phase 2 — Preview-feature system + signing

1. **`previewFeatures` mechanism.** A workspace-level (`tailor.yaml`) list of
   opt-in feature names. Using a gated capability without listing it is a **hard
   error at load time**, naming the feature to enable. Reusable for any future
   not-yet-stable capability.
   - Files: `tailor-config/src/schema.rs` (`preview_features: Vec<String>` on the
     workspace), `loader.rs` (gate check), a small `PreviewFeature` enum in
     `tailor-config`.
2. **`signing` is the first gated feature.** The e2e-proven `ic-sign` backend
   moves behind `previewFeatures: [signing]`. A `signing:` block without the
   opt-in is a hard error (replaces today's blanket "not implemented" stop).
   - Rebase the `ic-sign-signing` branch onto main; wire the preview gate in
     front of it. Flip `signing-status.md` to reflect "preview".
3. **`azure-key-vault`: implement under the signing preview feature** rather than
   rejecting it — it becomes a signing key source available only when `signing`
   is enabled.

## Phase 3 — Config hygiene

1. **Remove the inert `injectFiles` field.** With `deny_unknown_fields` it then
   produces a clear rejection if used. (IC's inject-files pass remains an
   internal detail of the signing flow.)
   - Files: `tailor-config/src/schema.rs`.
2. **Keep `skip`, document it.** No rename; add clear reference docs for the
   bulk-exclusion behavior.
3. **Validation stays render-time.** No new `validate()` phase for 1.0; keep the
   existing render-time surfacing. (Revisit post-1.0 if error ergonomics demand.)

## Phase 4 — Clones as a real feature

Clones build N images from one config that share all meaningful content but
differ in incidental details (random UUIDs, mtimes). **Today they overwrite each
other**: working copy / build dir / intermediate / log are clone-suffixed, but
the *final artifact path and the stamp are keyed by slug only* — so only the
last clone survives.

1. **Suffix the artifact and stamp per clone: `<slug>_clone<N>.<ext>`** so each
   clone is retained as a distinct image.
   - Files: `tailor-exec/src/arg_builder.rs` (`artifact_path`/`artifact_name`),
     `executor.rs` (`ic_output_path`/`published_path`), stamp keying in
     `tailor-core`.
2. **Clones always rebuild.** Because each clone is intentionally
   non-deterministic, an up-to-date/stamp skip is meaningless for clones —
   bypass the up-to-date check for clone runs.
3. Docs: describe clones as a supported feature (distinct-but-equivalent images),
   not a stress knob.

## Phase 5 — Safety

1. **Trusted-host threat model.** Commit `THREAT-MODEL.md`: guards defend against
   **accidents** (the `rm -rf /` class of event), not a malicious operator
   feeding hostile config on a trusted host. This bounds guard scope.
2. **Minimal hardening** (consistent with the trusted-host model): **pin the
   janitor container image by digest** (always the exact reviewed image) and
   document the trust boundary. Symlink/TOCTOU/`openat2` work is out of scope for
   1.0 (defends against malice, which the threat model excludes).
3. **Build-dir prevention guard ships regardless** (from the restoration plan):
   fail-closed if a resolved build/tools dir is `/`, an ancestor of `/`, or on
   `/`'s device; never construct `--tools-dir /`.

---

## Phase 6 — CLI contract

1. **`lock` vs `update` become distinct.** `lock` freezes the currently selected
   inputs; `update` re-resolves to the latest versions, then freezes (Cargo/npm
   convention). Today they are identical.
   - Files: `tailor/src/run.rs` (`Command::Update` split from `Command::Lock`),
     `cli.rs` help text.
2. **Extend lock coverage.** The lockfile pins base image + toolchain today;
   extend it to also pin **rpmSources, extraDependencies, inputs, tools-dir, and
   the engine version**.
   - Files: `tailor-core/src/lockfile.rs`.
3. **Exit-code taxonomy.** Adopt and document: **2 = usage error**, **1 = build
   failure**, **130 = SIGINT**. Wire through the CLI error mapping.
   - Files: `tailor/src/main.rs`/`run.rs` error→exit mapping; documented in
     `COMPATIBILITY.md`.
4. **Machine-readable output: deferred** to post-1.0 (`--format json` not shipped
   for 1.0).

---

## Phase 7 — Release, provenance & repo hygiene

1. **Full release provenance (SLSA level).** `release.yml` gains, in order:
   **version==tag check**, **full test-gate before publish**, **cosign keyless
   (OIDC) signing** of release binaries, a **CycloneDX SBOM**, and a **SLSA
   provenance attestation**. Add a verify snippet to the docs.
2. **Pin the toolchain and actions.** Pin the Rust toolchain to an explicit
   version (`rust-toolchain.toml`) and pin GitHub Action SHAs — closes the
   clippy-drift that has bitten CI twice.
3. **`CHANGELOG.md`** — committed, Keep-a-Changelog style, updated per release.

---

## Deferred to post-1.0

- **Parallel builds** — DAG scheduler across independent nodes, `--jobs`
  activation, cancel-all, progress, resource sanity. Groundwork (atomic writes,
  single-worktree guard) lands in 1.0; the scheduler is a design-doc follow-up.
- **Machine-readable output** — `--format json` for read verbs + a build-result
  schema, once the contract is worth promising.
- **Load-time `validate()` phase** — if render-time error ergonomics prove
  insufficient.
- **Deeper safety hardening** (symlink/TOCTOU/`openat2`) — only if the threat
  model ever widens to untrusted config.
- **Inter-image-deps roadmap** — the `§9` open items from
  `2026-09-09-inter-image-dependencies.md` (base-references-input,
  extraDependencies/rpmSources convergence, fan-in).
