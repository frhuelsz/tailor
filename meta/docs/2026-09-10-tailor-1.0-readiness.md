# tailor — 1.0 readiness assessment

> **Status:** _review · 2026-09-10._ Synthesis of a seven-track expert critique (architecture,
> config/schema, CLI/UX, build engine, execution/safety, testing/release, features/docs) against the
> bar for a **stable 1.0**. Verdict below; findings are severity-tagged with `file:line` citations.

## Verdict

tailor is a **strong, featureful late-0.x**: clean hexagonal shape, deterministic render + matrix,
content fingerprints + incremental stamps, real dual-arch E2E, and a coherent config surface. It is
**not yet 1.0**, for one dominant reason and a short tail of concrete bugs:

**1.0 is a *contract*, and tailor hasn't declared one.** There is no enforced schema version, no
semver/API/CLI-output/slug stability policy, an over-broad public library surface, and no release
provenance. Plus a handful of real correctness gaps (stale-after-upgrade, selector-excludes-producer)
and one large advertised-but-unshipped feature (signing). Fix the contract + the correctness bugs +
resolve the signing story, and tailor is 1.0-ready. Everything else is post-1.0 roadmap.

---

## P0 — 1.0 blockers (must fix)

### Stability contract (the core of "1.0")
- **`schemaVersion` is parsed but never enforced** — `schema.rs:24` deserializes `schema_version: u32`
  with no check it equals the supported version; `schemaVersion: 2` silently gets v1 behavior, and
  `image.yaml`/fragments carry no version at all. Add `CURRENT_SCHEMA_VERSION`, reject unsupported
  majors with a dedicated error, and decide image/fragment inheritance. (`loader.rs`, `schema.rs`)
- **No published stability policy.** Commit a `COMPATIBILITY.md`/`STABILITY.md` covering: semver for
  the CLI; config-schema compatibility + migration; **slug/filename stability** (they're public — CI
  and scripts depend on them); CLI **exit-code** and **stdout** contracts; lockfile format; MSRV; and
  a deprecation policy. This is the single biggest gate.
- **Over-broad public API = accidental semver commitments.** `tailor-core/src/lib.rs:3-25` exposes
  implementation modules (`ado`, `catalogue`, `hashcache`, `lockfile`, `stamp`, `testing`, …) and
  `tailor-exec/src/lib.rs` exposes `path_translate`/`rpm_farm`/`working_copy`. Make internals
  private, expose a curated façade, or mark crates explicitly "not a stable library" for 1.0.
- **Release provenance is absent.** `release.yml` publishes checksums only — no version/tag==Cargo
  check, no test gate on release, no artifact signing / SBOM / attestation, and `workflow_dispatch`
  can publish an arbitrary tag. Add a version-consistency job, gate release on CI-quality tests, and
  add keyless signing + SBOM + a committed `CHANGELOG.md`.

### Correctness bugs (incremental engine)
- **Stale artifacts after a tailor upgrade.** `stamp::is_up_to_date` (`stamp.rs`) compares only the
  fingerprint + artifact existence; the recorded `tailor_version` is ignored, and the engine version
  is **not** a fingerprint input. A changed executor/arg-builder/signing/format reuses old artifacts
  forever. **Fix (small, safe):** fold an explicit `BUILD_SCHEMA_VERSION` into the fingerprint.
- **A selector can exclude a producer cell a consumer needs.** The same `Selector` is applied to
  every topological node in the build loop (`run.rs` build driver); `tailor build consumer -s …` can
  drop the producer's paired cell, so `imagedep` resolves a path to an artifact that never builds.
  **Fix:** union each producer's dependency-required coordinates into its selection (or build
  dependency cells unfiltered, applying the selector only to requested outputs).

### The signing story
- **Signed builds hard-stop on `main`.** The e2e-proven `ic-sign` backend lives on the unmerged
  `ic-sign-signing` branch; on `main`, `tailor build` refuses signed builds and dry-run reports "not
  implemented", yet `signing:` is an accepted schema field and `meta/docs/2026-06-29-signing-status.md`
  reads as if shipped (doc-vs-code drift). **Decide for 1.0:** either merge + test the full
  `customize → sign → inject-files` path, or **remove `signing:` from the supported surface** and mark
  it experimental. Do not ship an accepted field that silently can't build.

## P1 — should fix before 1.0

### Config footguns
- **`injectFiles` is an inert, documented no-op** (`image-yaml.md:24`) that still feeds the
  fingerprint. Remove it or reject it with a migration error.
- **`azure-key-vault` signing backend is schema-only** — validates but can never build. Reject it as
  unsupported (or implement) rather than accepting apparently-valid config.
- **Load-time validation is thin.** `load_image` only parses; selectors-without-matrix,
  missing/ambiguous base, output rules, and reference existence (`toolchains.default`, `base.ref`,
  `toolsDir.source`, `inputs.image`, `dependsOn`) are deferred to render. Add an
  `ImageDefinition::validate()` + central catalogue-reference validation so `validate` and editors
  catch errors pre-expansion with source context.
- **`skip` is overloaded** ("excluded from bulk, still buildable") and easy to misread as "never
  build." Consider `excludeFromBulk`/`selection:` and a documented precedence truth-table surfaced in
  `explain`.
- **`OutputSpec.name` is unrestricted** — no validation for duplicates, path separators, or
  cross-format collisions after expansion.

### Engine robustness
- **Non-atomic writes.** Stamps (`stamp.rs`) and artifacts publish via `fs::write`/`rename` without
  the temp-file → `fsync` → atomic-rename discipline; an interrupt can leave a truncated stamp or a
  partial artifact treated as complete. Publish build→temp→fsync→rename as a unit; write an
  "incomplete" marker until finalized.
- **`(size, mtime)` hash cache is unsound under in-place writes / coarse mtime** (`hashcache.rs`):
  stat→read without a re-stat, hash cached under the pre-read tuple. Add stat–read–stat-and-retry, and
  document "inputs must not mutate mid-build."
- **Same-cell/concurrent builds are unsafe** — stamps/artifacts/goldens/cache/working-copies are
  keyed by slug and only safe because the loop is sequential. Add per-cell/worktree locking before any
  parallelism ships.
- **`lock` is not a full reproducibility manifest** — pins registry base + toolchain digests but
  excludes `rpmSources`, `extraDependencies`, `${inputs}`, tools-dir content, and the engine version.
  Add a content manifest verified in locked builds (and consider BLAKE3/SHA-256 for *persisted*
  identities; XXH3 is fine for change-detection only).

### Execution & safety (frame the trust model, then harden)
- **Document the threat model.** `--privileged -v /dev:/dev` is a **trusted-host** operation, not a
  sandbox (`arg_builder.rs:18`, `runtime.rs`). State this explicitly: the guards defend against
  **accidents** (the historical `rm -rf /`), not malicious config. That reframes the items below.
- **Cheap hardening wins:** pin the janitor image by **digest** (it runs privileged with host binds —
  `janitor.rs`); add TOCTOU/symlink resistance to janitor removal + rpm-farm delete (canonicalize /
  `--one-file-system` / reject mountpoints — `guard.rs`, `janitor.rs`, `rpm_farm.rs`); make
  cancellation teardown fail-closed with stop→kill→remove retry + a stale-container sweep by label
  (`runtime.rs`).
- **Signing atomicity** (if signing ships): temp files with `O_EXCL|O_NOFOLLOW`, atomic rename,
  exclusive CA publication (`tailor-sign/src/lib.rs`).

### CLI / automation contract
- **`update` == `lock`** — both dispatch to `lock()` (`run.rs:157`). Make `update` re-resolve mutable
  refs vs `lock` preserving pins, or drop `update`.
- **`--jobs` is accepted but ignored** (sequential build). Implement bounded parallelism or hide the
  flag until it works.
- **Exit codes are binary** (`main.rs`) — everything is `FAILURE`. Define a taxonomy (2 = usage/config,
  1 = build failure, 130 = SIGINT) and test it.
- **No machine-readable output** for `list`/`validate`/`render`/`export`/`clean`/`bases`/build
  results — only `matrix` has JSON/ADO. Add `--format json` (+ a per-cell build-result schema:
  selected/skipped/up-to-date/built/failed, artifact paths, durations, cache hit/miss) with
  diagnostics strictly on stderr.

## P2 — post-1.0 roadmap (defer, but plan)

- **Cross-cell/image parallelism** with dependency-aware scheduling, cancellation, `--keep-going`, and
  deterministic aggregation (unblocks `--jobs`).
- **`inputs:` Phase 3** — `path`/`oci`/`url` input kinds, fan-in, cell-level dependency edges
  (`meta/docs/2026-09-09-inter-image-dependencies.md` §9).
- **Shared/remote build-result cache** keyed by the full content-addressed build key.
- **Supply chain:** first-class SBOM + artifact provenance for *produced images* (not just releases).
- **Runtime portability:** documented support matrix; remote TLS/SSH endpoints
  (`connection.rs:29-32`); rootless/podman troubleshooting.
- **Golden/snapshot suite** for the config surface, enforced in CI (render goldens exist but aren't a
  committed regression gate).

## Code-quality items

- **Error taxonomy** loses structure (`ExecError::Runtime(String)`, `ResolveError::…{detail:String}`,
  broad `Other(String)`) and the CLI re-wraps core errors 1:1 (`tailor/src/error.rs`). Preserve typed
  sources; document the "typed library errors → one app error at the boundary" rule.
- **Port DTOs are public-field structs** (`ports.rs` `ExecutionContext`/`RuntimeConfig`/
  `ContainerConfig`/`SigningPlan`) — adding a field is source-breaking for every adapter. Use
  builders/constructors with private fields if these are meant to be stable.
- **`tailor-core` depends on `tailor-config` types** in its domain/ports (`domain.rs`, `ports.rs`):
  fine if "core is not a standalone reusable library" is stated; otherwise introduce a core-owned
  boundary type. Decide and document.
- **Pin the toolchain** — `rust-toolchain.toml` floats `stable` and CI floats `setup-rust-toolchain@v1`,
  so clippy drifts (this bit us twice this cycle). Pin the channel + action SHAs; test the MSRV.

## Recommended path to 1.0

1. **Ship the contract** (P0 stability): enforce `schemaVersion`; write the stability policy +
   `CHANGELOG.md`; curate the public API; add release version-check + test-gate + signing/SBOM.
2. **Fix the P0 correctness bugs**: engine version in the fingerprint; selector∪producer-coordinates.
   Both are small and self-contained.
3. **Resolve signing**: merge + test `ic-sign`, or gate `signing:` as experimental. Reconcile the
   status doc.
4. **P1 sweep**: remove `injectFiles`; atomic writes; load-time validation; janitor digest-pin +
   TOCTOU; `update`/`lock` split; exit-code taxonomy; `--format json` for read verbs; hide/implement
   `--jobs`.
5. Tag **1.0** once 1–3 are done and P1 is substantially complete; carry P2 as the post-1.0 roadmap.

**Quick wins (small, safe, high-value — good first cut):** enforce `schemaVersion`; fold a build-schema
version into the fingerprint; hide `--jobs` until implemented; reject `injectFiles`/`azure-key-vault`
with clear errors; pin the toolchain + CI action SHAs; make stamp/artifact writes atomic.
